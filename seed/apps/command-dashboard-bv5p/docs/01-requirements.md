### constraints

- 数据策略为 live_api：必须接入公开潮汐预测 API 实时取数，禁止内置固定潮汐曲线或 mock 数据；任一港口取数失败须在该格显式报错，不得伪造数据或静默降级。
- 阈值判定口径：12.8 米吃水阈值须换算至与各港潮高同一基准后比较，潮高连续满足阈值的时段判定为该港可出港时间窗。
- 范围固定：监测港口固定为诺福克、圣迭戈、布雷默顿、横须贺四港（需求中已显式命名，carrier-affiliation-data-skill 仅作母港背景参考，无需动态舰船归属推断），潮汐序列覆盖未来 72 小时。
- 刷新要求：每 10 分钟自动刷新一次，当前潮高、窗口开闭状态与倒计时须随刷新同步更新。
- 蓝图引用 carrier-homeport-tide-window 仅作参考场景文档：其客户口径（四港、72 小时、12.8 米阈值、绿/红状态、10 分钟刷新）与 UI 结构可参考，但其 mock 数据实现与演示加速 tick 不适用于本任务，一切以确认需求的 live_api 口径为准。

### description

本需求旨在为母港出港调度/指挥人员提供一款实时潮汐出港窗口监测看板。目标是接入公开潮汐预测数据源，替代人工查表，辅助调度人员把握航母出港时机。范围覆盖诺福克、圣迭戈、布雷默顿、横须贺四大航母母港，取数窗口为未来 72 小时，数据策略为 live_api，即必须从真实公开 API 取数，取数失败时显式报错，禁止伪造潮汐数据。关键能力包括：按 12.8 米吃水阈值（换算至与潮高同一基准后比较）计算各港连续可出港时间窗；以 2×2 四格看板展示各港港口名、当前潮高、是否满足出港条件与下一窗口起止时间，窗口开放显示绿色、关闭显示红色倒计时；每 10 分钟自动刷新一次，潮高、窗口状态与倒计时随刷新同步更新。

### risks

- 横须贺港位于日本，公开潮汐预测 API 的规范性与可用性弱于覆盖诺福克、圣迭戈、布雷默顿的 NOAA 系源，可能需要备选公开数据源；若无法稳定取数，按验收口径该格须显式报错，将影响其可用性。
- 各港潮高基准（如平均低低潮、平均海面等）不一致，12.8 米阈值的基准换算若出错，会导致窗口起止时间与开闭状态出现系统性偏差。
- 四港分布在不同时区（美东、美西、日本），窗口起止时间、倒计时与最近刷新时间的时区换算与展示口径需统一，否则易出现跨港对比错误。
- 公开 API 存在限流与瞬时不可用风险，10 分钟周期刷新可能出现部分港口成功、部分失败，四格看板需保证各港成功态与错误态独立呈现、互不影响。

### summary
