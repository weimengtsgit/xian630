## 2026-08-16 · v12：航向来源恢复生产版本字段优先级 + 弹窗跳变消除 + 渲染序列后端化

### 背景
上一轮（v11）把关联算法航向来源改成了"只读 orientation 列"。经确认：客户对字段名称的描述基于其 CSV/算法环境，与本体 AIS 数据字段不完全一致（本体无独立 orientation 字段，北邮 CSV 中 heading 列约 95% 为 511 不可用标记、orientation 列全有效，两者语义不能强行互换）。按客户确认原则：**航向数据来源沿用修改前生产版本的字段优先级与映射，不做 orientation-only**。

### 改动
1. **航向来源（server/carrierAffiliation.js）**：新增 `resolveAnalysisHeading(point)` 纯函数，逐字保持修改前（v10 之前）的取值优先级 `heading → courseDeg 兜底`（heading 即本体 trueHeading，courseDeg 即本体 courseOverGround）；客户确认的缺失规则作用于解析结果——511/null/空串/非数值 → 该点航向缺失（511 不触发兜底，保持旧版 `??` 语义）。删除 v11 的 orientation-only 及"本体无 orientation 故用 courseOverGround 伪装"的说明。整轨无有效航向的配对不分析，原因字段改为 `insufficient_heading_data`，前端展示"航向数据不足，未进行关联分析"。
2. **弹窗跳变消除（src/app/VesselFocusPanel.jsx + src/logic/trackRenderCache.js）**：弹窗打开后不再"先画快照图再静默替换"。状态机：loading（占位"正在加载航迹数据…"，不挂载 SVG）→ settled 后一次性绘制：双侧成功 full / 单侧成功 partial（快照回退）/ 双侧失败 snapshot（快照回退）/ 无快照数据 error（空状态）。AbortController：关闭弹窗、切换关联对象（弹窗按关联 key 重建）时取消未完成请求；已完成结果缓存复用、in-flight Promise 合并，同一 MMSI 不重复请求。图例文案与状态一致（full 标注"服务端全量轨迹生成的渲染序列"，不宣称浏览器全量逐点绘制）。
3. **大轨迹渲染后端化（server/app-server.js + src/logic/renderDecimation.js）**：track 接口新增 `?render=1`，服务端从全量轨迹生成分桶抽稀渲染序列（合法经纬度过滤、保留首尾、每桶经纬度极值、上限 3000 点），meta 返回 sourcePointCount/renderPointCount/renderLimit/renderedFromFullTrack。前端航迹图只消费渲染序列，不再下载/扫描十万级完整点数组。抽稀实现提取为无 React 依赖的纯函数模块前后端共享；仅影响显示，不改变关联计算、距离统计、命中结论或完整数据导出（无参 track 接口保持全量）。距离曲线仍为快照全量序列 + 前端渲染层抽稀。
4. **sourceOrder 数据源限制（如实记录）**：本体 AIS 查询仅返回所选业务列，无稳定原始记录 ID/入库序字段，且分页模式不可用（同报点约 32 倍重复 ingest）。因此"同秒第一条"按当前轨迹存储顺序确定（cleanTrack 内 (秒, 输入位置) 稳定排序），**不是源数据严格意义的第一条**——数据源限制，不以随机/Map/hash 顺序冒充。轨迹存储结构未变（未持久化 sourceOrder），无需判废轨迹缓存。
5. **快照判废**：`affiliationRulesChanged` 现同时比较算法版本、CARRIER_AFFILIATION_RULES 与 CARRIER_AFFILIATION_DATA_RULES；快照版本升至 `customer-confirmed-v12-20260815`，dataRules 增加版本号并改为事实性描述（`headingSource: "legacy-pre-v11-field-precedence"`、`headingFieldPrecedence: ["heading","courseDeg"]`，不再写 orientation-only）。旧快照自动判废重算。
